# Phase 4 — UI Design Contract

> Visual and interaction contract for `PaywallView` and the `ScoreBarView` free-puzzle-counter addition. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native SwiftUI, no shadcn/npm in this project |
| Preset | not applicable |
| Component library | none — native SwiftUI controls only (`Button`, `ProgressView`, `VStack`/`HStack`, `TimelineView`) |

## Spacing Scale

Declared values (inherited unchanged from `GameTheme.swift`, all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (e.g. inside the free-puzzle-counter badge) |
| sm | 8px | Compact stacks (stat row internal spacing, header sub-line gaps) |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding — screen edges, block-to-block gaps |
| xl | 32px | Layout gaps between major PaywallView blocks (countdown block → stats block → CTA block) |
| xxl | 48px | Major section breaks (header → content, content → CTA footer) |

Exceptions:
- `GameTheme.minTapTarget` (44pt) applies to the "Restore Purchases" text link's tappable area (via `.frame(minHeight: 44)` even though the visible text is smaller than 44pt) — Apple HIG minimum, same rule already applied to the icon-only Shuffle/Delete buttons in `GameView`.
- No 64px/`3xl` tier — `GameTheme` does not define one and Phase 3 never needed it; Phase 4 does not introduce it either. `xxl` (48) is the largest gap in this contract.

## Typography

Declared values (inherited unchanged from `GameTheme.swift` — exactly 4 sizes, 2 weights, no new ones added):

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Display | 34px | Semibold | System default | The live-ticking countdown value itself (e.g. "2h 14m") — the single largest, most prominent element on the paywall, reinforcing D-06's "live, not static" requirement |
| Heading | 20px | Semibold | System default | "Unlock Unlimited Puzzles" section title; the price line (e.g. "$2.99"); "Today's Stats" section label |
| Body | 17px | Regular | System default | Primary CTA button label; stat row values; error/failure inline text |
| Label | 13px | Regular | System default | "Next free puzzle in" caption above the countdown; stat row captions ("Puzzles today", "Streak", "Score", "Words found"); Restore Purchases link text; free-puzzle-counter text in `ScoreBarView` |

No explicit line-height ratio is set anywhere in `GameTheme.swift` (Phase 3 relies on `Font.system`'s default metrics) — Phase 4 follows the same precedent, no new line-height token needed.

## Color

Declared values (inherited unchanged from `GameTheme.swift`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Color(.systemBackground)` | PaywallView full-screen background |
| Secondary (30%) | `Color(.secondarySystemBackground)` | Today's-stats card container, free-puzzle-counter badge background |
| Accent (10%) | `Color.accentColor` (#F5B800 honeycomb gold) | Reserved for: the primary "Unlock Unlimited Puzzles" CTA button (background/tint), the price text ("$2.99"), and the countdown's Display-font numeral. Nothing else on this screen uses accent. |
| Destructive/Error | `Color(.systemRed)` (`GameTheme.errorColor`) | Purchase-failure and restore-failure inline messages only |

Accent reserved for: the Unlock CTA button, the price text, and the countdown numeral — three elements total, all tied to the "unlock" sales message. Explicitly NOT used for: "Restore Purchases" (must not compete visually per D-09), stat values in the today's-stats block (those stay `Color.primary`/`Color.secondary` to keep the sales CTA the only accented element), or the free-puzzle-counter in `ScoreBarView` (stays `Color.secondary`/`Color.primary`, matching the existing found-word-count label style — it's informational, not a call to action).

## Screen Layout — PaywallView

Full-screen, dead-end presentation (D-05: no dismiss, no blurred game screen behind it). Presented via `.fullScreenCover`, the same mechanism `GameView` already uses for `MissedWordsView` — no new presentation pattern introduced. Root container: `ScrollView` wrapping a `VStack(spacing: GameTheme.xl)` so the screen degrades gracefully on smaller devices (iPhone SE) without clipping content — do not use a fixed non-scrolling `VStack` for the whole screen.

Top to bottom:

1. **Countdown block** (`VStack(spacing: GameTheme.sm)`, centered, top padding `GameTheme.xxl`)
   - Label-font caption: `"Next free puzzle in"`
   - Display-font, accent-colored, live-ticking value: `"2h 14m"` (see Copywriting Contract for exact format rules)
   - Driven by `TimelineView(.periodic(from: .now, by: 1))` recomputing the remaining interval every second against local midnight (per D-06's boundary requirement) — ticking at 1-second resolution satisfies "live," even though the displayed granularity is minutes (seconds are not displayed except in the sub-1-minute case, see Copywriting Contract).

2. **Today's stats card** (`VStack`, background `GameTheme.secondarySurface`, `RoundedRectangle(cornerRadius: 12)`, padding `GameTheme.md` — same card treatment as `ScoreBarView`'s existing container)
   - Heading-font section title: `"Today's Stats"`
   - 2x2 grid or 4-row stack of stat pairs (Label-font caption + Body-font value), in this fixed order: Puzzles played today, Current streak, Today's total score, Today's words found
   - All four values render even when zero (e.g. an all-abandoned-rounds day) — zero is valid content here, not an empty state; see Copywriting Contract "Zero-data fallback"

3. **CTA block** (`VStack(spacing: GameTheme.md)`, bottom-anchored, padding `GameTheme.lg`)
   - Heading-font, accent-colored price line: `unlimitedProduct?.displayPrice ?? "—"`
   - Primary button (`.buttonStyle(.borderedProminent)`, tinted `GameTheme.accent`, `minHeight: GameTheme.minTapTarget`, `frame(maxWidth: .infinity)`) — Body-font label `"Unlock Unlimited Puzzles"`
   - Inline error text slot below the button (Body-font, `GameTheme.errorColor`, empty/hidden when no error) for purchase failures
   - Restore Purchases: `Button` styled as a plain text link (`.buttonStyle(.plain)`, Label-font, `Color.secondary`, NOT accent-tinted), `minHeight: GameTheme.minTapTarget` for tap-area compliance, positioned directly below the primary CTA per D-09
   - Second inline error text slot below Restore for restore-failure messaging

No new component library, no new colors, no new icons beyond SF Symbols already in use. `PaywallView` follows the same value-in/closure-out contract as `MissedWordsView` and `ScoreBarView` (per 04-CONTEXT.md's Established Patterns) — it must not reach into `EntitlementStore`/`PersistenceStore` via `@Environment` directly; the values (price, countdown target, stat numbers) and closures (`onUnlock`, `onRestore`) are passed in from `GameView` or `WordPuzzleApp`, consistent with Phase 3's "only GameView touches the view model" rule extended to this phase's data sources.

### ScoreBarView addition (free-puzzle counter, D-03/D-04)

Add a Label-font, `Color.secondary` text to the existing `HStack` in `ScoreBarView`, alongside the current `"\(foundCount) of \(totalCount) words"` text — same row, same font, same color treatment, just a second line or trailing fragment. Only rendered when the player is non-premium (`isPremium == false`); nothing renders in this slot for premium users (per D-03, no new layout reserved for it — the row simply doesn't gain the extra text). Exact copy: see Copywriting Contract.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `"Unlock Unlimited Puzzles"` (button label) with price shown as a separate prominent line above it: `unlimitedProduct.displayPrice` (e.g. `"$2.99"`), per D-08's "presented prominently and literally" |
| Countdown caption | `"Next free puzzle in"` |
| Countdown value format | `"{H}h {M}m"` when ≥ 1 hour remaining (e.g. `"2h 14m"`); `"{M}m"` when < 1 hour (e.g. `"42m"`); `"Less than a minute"` when < 60s remaining. Always computed against local midnight (`Calendar.startOfDay(for:) + 1 day`), matching `PersistenceStore.puzzlesPlayedToday()`'s existing boundary per D-06 |
| Today's-stats section label | `"Today's Stats"` |
| Stat captions | `"Puzzles today"`, `"Streak"`, `"Score"`, `"Words found"` |
| Zero-data fallback | Not a true empty state — all four stats always render as numerals, including `0`, when a day consisted only of abandoned rounds (D-02). No special empty-state message; `0` reads as valid content, matching `ScoreBarView`'s existing `"0 of N words"` precedent during a fresh round |
| Restore Purchases link | `"Restore Purchases"` |
| Purchase error state | `"Purchase failed. Check your connection and try again."` — inline, `GameTheme.errorColor`, below the primary CTA |
| Restore error state | `"No previous purchase found for this Apple ID."` — inline, `GameTheme.errorColor`, below the Restore link |
| Free-puzzle counter (ScoreBarView, non-premium only) | `"{remaining} of 3 free puzzles today"` (e.g. `"2 of 3 free puzzles today"`), where `{remaining} = 3 - puzzlesPlayedToday()`, clamped to 0 |
| Destructive confirmation | None in this phase — no destructive/data-loss actions exist on the paywall (Unlock and Restore are both additive, non-destructive) |
