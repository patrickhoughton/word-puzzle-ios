# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native SwiftUI (iOS 17.6 target); shadcn/component-registry tooling is React-specific and not applicable to this platform |
| Preset | not applicable |
| Component library | none — all views are hand-built SwiftUI (`Shape`, `View`), per CLAUDE.md's "hex tile via custom Shape/ZStack clip" and "no third-party dependency" guidance. Confirmed via RESEARCH.md: zero SPM package references in `project.pbxproj` |
| Icon library | SF Symbols (system-bundled, no asset work required) — `shuffle` (Shuffle button), `delete.left` (Delete button), `checkmark.seal.fill` (pangram badge on missed-words screen) |
| Font | System font (San Francisco) via `.font(.system(size:weight:))` — no custom font files. Dynamic Type scaling is explicitly deferred to Phase 5 (UX-03); Phase 3 uses fixed point sizes below |

**Note on scope:** `.planning/REQUIREMENTS.md` lists an "NYT-style hex honeycomb layout" under Out of Scope (App Store 4.3 clone-risk). `03-CONTEXT.md` D-01 explicitly overrides this with a locked decision to build the honeycomb hex layout. Per RESEARCH.md Pitfall 5, this override is intentional and discussed, not an oversight — flagged here again for visibility since it affects nearly every visual element in this spec (hex tiles, honeycomb-gold accent color below).

**Existing asset found during scouting:** `Assets.xcassets/AccentColor.colorset` exists but is currently unset (defaults to system blue). This spec repurposes it — see Color section.

**Visual hierarchy:** Primary focal point on GameView is the in-progress word display (Heading-size, above the hex grid) together with the center hex tile it builds from. The hex grid is the primary interactive surface; the ScoreBar (rank tier + found-count) is secondary, positioned above but visually subordinate via smaller type (Label size) and the Secondary surface color. On the missed-words screen, the primary focal point is the length-grouped word list itself; the rank tier / "Perfect Round!" headline is secondary framing above it.

## Component Geometry

Off-grid values driven by hex-grid trigonometry, not independently chosen — kept out of the Spacing Scale below to avoid ambiguity with the spacing-grid contract:

- Hex tile diameter: **70pt** (per RESEARCH.md Pattern 2, tune visually on-device, keep within 64–72pt)
- Outer-ring radius: `hexSize * 1.6` (~112pt), derived from hex tile diameter

Minimum tap target: **44×44pt** on every interactive element (each hex tile, Shuffle, Delete, Finish) per Apple HIG — apply via `.contentShape` padding if the visual hex/icon is smaller. This is a HIG compliance floor, not a spacing-scale value.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between hex letter glyph and its tile edge; gap between "+N" popup and word display |
| sm | 8px | Gap between missed-word list rows; gap between rank tier name and found-count subtext |
| md | 16px | Padding inside word-display card; gap between ScoreBar and hex grid; padding around missed-word-group headers |
| lg | 24px | Section padding: top of GameView safe area to ScoreBar; padding around missed-words list container |
| xl | 32px | Gap between hex grid and bottom control row (Shuffle/Delete/Finish) |
| 2xl | 48px | Vertical gap between word-display card and hex grid |
| 3xl | 64px | Not used in Phase 3 (no page-level multi-section layout) |

Component-sizing exceptions (hex tile diameter, outer-ring radius, minimum tap target) are documented separately in the "Component Geometry" section above — this scale covers gap/padding spacing only, all clean multiples of 4.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 17px | regular (400) | 1.5 |
| Label | 13px | regular (400) | 1.5 |
| Heading | 20px | semibold (600) | 1.2 |
| Display | 34px | semibold (600) | 1.2 |

**Usage map:**
- **Display (34/600):** hex tile letters; the "+N" points popup (D-08); rank tier name on the missed-words screen headline
- **Heading (20/600):** in-progress word display above the hex grid (D-04); missed-word length-group headers ("4 Letters", "5 Letters" — D-11); rank tier name in the live ScoreBar
- **Body (17/400):** missed-word list items; "Finish Round" button label; "Not a valid word" message (D-07); empty-state body copy
- **Label (13/400):** found-word count subtext under the rank tier name (e.g. "12 of 31 words"); accessibility captions under icon-only Shuffle/Delete buttons

Exactly 4 sizes, exactly 2 weights — no additional sizes/weights introduced.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Color(.systemBackground)` — semantic (light `#FFFFFF` / dark `#000000`) | GameView root background behind the hex grid; missed-words screen background |
| Secondary (30%) | `Color(.secondarySystemBackground)` — semantic (light `#F2F2F7` / dark `#1C1C1E`) | Word-display card surface; missed-word list row background; ScoreBar container background |
| Accent (10%) | `#F5B800` (honeycomb gold) | See "Accent reserved for" below |
| Destructive/Error | `Color(.systemRed)` — semantic (`#FF3B30`) | Invalid-word shake message text only (D-07). No destructive-confirmation actions exist in Phase 3 (see Copywriting) |

**Accent reserved for:**
- Center hex tile fill (the visually-distinguished required-letter tile per D-01/GAME-01)
- "+N" points popup text and pop/highlight flash on correct submission (D-08)
- Shuffle button icon
- Pangram badge/highlight on the missed-words screen (D-11)
- Active rank-tier progress fill in the ScoreBar (D-09)

**Implementation note:** Set the existing (currently unset) `Assets.xcassets/AccentColor.colorset` to `#F5B800`. This makes it the app-wide tint color, so default-styled SwiftUI controls (`.tint()`, `Button` default style) pick it up automatically without per-view color literals.

Outer (non-center) hex tiles use the Secondary surface color, not a third color — this keeps the palette at the required 60/30/10 split without adding an unlisted fifth color.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Finish Round" (ends the round manually per D-10; no auto-end) |
| Empty state heading | "Perfect Round!" — shown on the missed-words screen only when `missedWords` is empty (user found every valid word) |
| Empty state body | "You found every word. Nothing missed — nice work." |
| Error state | "Not a valid word" — exact generic text per D-07; word display shakes simultaneously. No reason-specific variants (already-found / too-short / missing-center-letter / not-in-list) — explicitly deferred, see CONTEXT.md Deferred Ideas |
| Destructive confirmation | None in Phase 3 — "Finish Round" is a normal round-ending action (not data-destructive: missed words were never "collected," so nothing is lost that requires a confirmation dialog). Tapping the assembled word to clear it (D-05) is also non-destructive and requires no confirmation |

**Supporting copy (not template rows, but load-bearing for this phase):**
- "+N" points popup: literal `+{points}` (e.g. "+12"), no extra words, per D-08 — Display-size, accent-colored
- Pangram bonus flourish: small "Pangram!" sub-label beneath the "+N" popup when the submitted word is a pangram (optional discretion resolution — omit if it complicates the pop animation, not load-bearing)
- Missed-words screen title: "Words You Missed"
- Missed-word length-group headers: "{N} Letters" (e.g. "4 Letters", "5 Letters")
- Pangram badge on a missed word: "Pangram" tag/label next to the word, accent-colored, per D-11
- Rank tier names (exact, per D-09 — do not reword, deliberately not NYT's names): Novice, Rookie, Apprentice, Wordsmith, Adept, Skilled, Expert, Virtuoso, Master, Legend
- Shuffle button accessibility label: "Shuffle Letters"
- Delete button accessibility label: "Delete Last Letter"
