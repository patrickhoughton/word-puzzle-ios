Existing tooling — `scripts/appstoreconnect.py` (built in Phase 2, verified
working against this account):

    python3 scripts/appstoreconnect.py get /v1/apps
    python3 scripts/appstoreconnect.py get "/v1/apps?filter[bundleId]=com.patrickhoughton.WordPuzzle"

Credentials live outside the repo at `~/.appstoreconnect/config.json` and
`~/.appstoreconnect/private_keys/AuthKey_<KEY_ID>.p8`. Reading records
(`GET /v1/apps`, `GET /v1/apps/{id}/inAppPurchasesV2`) is well-tested and safe.
Write endpoints are NOT exercised by this script and Apple's newer
create/update schemas drift — per the project's own recorded lesson, verify any
write payload against Apple's current OpenAPI spec before trusting it, or use
the web console instead. Prefer the console for writes in this plan; use the API
for read-back verification, which is where it is reliable.

Facts established by earlier Phase 5 plans that this plan depends on:
- D-06/D-07: TelemetryDeck is deferred to v2. v1 ships with ZERO analytics, zero
  SDKs, zero accounts and zero network calls. Plan 05-04's Guard 1 proves no
  networking API exists anywhere in the app target. Therefore every privacy
  questionnaire answer is "No" / "Data Not Collected" — there is no nuance to
  agonise over, and any answer other than "Data Not Collected" would be
  inaccurate.
- Plan 05-04 set `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` on both
  app-target configurations, and it lands in the built app's synthesized
  Info.plist. App Store Connect should therefore stop prompting for export
  compliance per upload.
- Plan 05-07 produced three captioned 1320x2868 screenshots at
  `Marketing/screenshots/final/`. Whether an iPad set is also required is
  recorded in `05-04-SUMMARY.md` and `Marketing/screenshots/README.md`.
- Plan 05-03 produced the three AppIcon appearance slots. The App Store listing
  icon is taken from the uploaded build's asset catalog automatically — it is
  not a separate upload — so a build must be uploaded for the listing icon to
  appear.

Facts from CLAUDE.md's App Store Connect section that shape the checkpoints:
- Missing or inaccurate privacy labels are among the most common first-submission
  rejection reasons.
- A missing "Restore Purchases" button is a Guideline 3.1.1 rejection. The app
  has one (MON-03, shipped in Phase 4) — the risk is the reviewer not FINDING
  the paywall, so Review Notes must spell out how to reach it.
- Mac and Vision Pro availability are auto-checked on new app records and must
  be unchecked unless tested there. Neither has been tested.
- Submit for Manual Release so launch timing stays under Patrick's control.

Known project hazard from STATE.md: Apple's sandbox purchase-history propagation
is unreliable and Simulator StoreKit testing is broken on this machine
(documented in 02-04 and 04-04). Do not attempt to re-verify IAP behaviour here
— MON-02/03/04 were already proven by a real sandbox purchase in Phase 4.
