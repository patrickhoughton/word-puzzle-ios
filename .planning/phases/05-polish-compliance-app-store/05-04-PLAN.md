  <context>
`project.pbxproj` currently declares `TARGETED_DEVICE_FAMILY = "1,2"` — Xcode's
default for new projects, never revisited in Phases 1-4. Every product document
describes an iPhone game: CLAUDE.md says "A Spelling Bee-style word unscramble
game for iPhone", and Phases 1-4 were built and tested exclusively on iPhone
Simulators and a physical iPhone.

Why this must be answered now rather than assumed:
- If iPad stays enabled, App Store Connect will require a 13" iPad screenshot
  set (2064x2752) in addition to the 6.9" iPhone set — expanding plan 05-07.
- The hex flower is a fixed-geometry layout (`GameTheme.hexSize = 70`,
  `outerRingRadius = hexSize * 1.6`). It has never been rendered at iPad width.
  Shipping iPad support without an iPad layout pass risks an Apple Review
  rejection for a stretched or broken iPad layout — a far more common rejection
  than most first-time submitters expect.
- The app is unreleased, so restricting now costs nothing. Restricting AFTER
  release is the expensive direction (existing iPad customers would lose
  updates), so the reversible choice is to narrow now and widen in v2.

05-UI-SPEC.md already adopted iPhone-only as its working default, explicitly
marked "pending confirmation" — this checkpoint is that confirmation.

**Recommendation: `device-family-iphone-only`.** It matches every stated product
constraint, removes an unbudgeted iPad screenshot + layout workstream from a
phase whose whole purpose is passing review on the first submission, and leaves
iPad as a clean v2 opportunity.
  </context>
