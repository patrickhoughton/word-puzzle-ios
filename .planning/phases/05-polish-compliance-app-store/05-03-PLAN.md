- `swift scripts/GenerateAppIcon.swift <args>` runs SwiftUI + `ImageRenderer` on

- `ImageRenderer.cgImage` is `@MainActor`-isolated. A top-level Swift script
  must wrap the render in an `@MainActor func` and call it via
  `MainActor.assumeIsolated { ... }`, or the script fails to compile with
  `#ActorIsolatedCall`.

  App Store rejection). Flatten by redrawing the CGImage into an opaque

  <action>
Create `scripts/GenerateAppIcon.swift` — a standalone macOS Swift script
(run as `swift scripts/GenerateAppIcon.swift <concept> <appearance> <output.png>`)
that renders the app icon with SwiftUI's `ImageRenderer` and writes a flattened,
alpha-free 1024x1024 PNG.

Required structure:

    #!/usr/bin/env swift
    // Reproducible app-icon generator (UX-04 / D-08).
    // Usage: swift scripts/GenerateAppIcon.swift <a|b> <light|dark|tinted> <out.png>
    // Renders at 1024x1024, strips the alpha channel (iOS icons must be opaque),
    // and writes a PNG. Requires no third-party tooling.
    import SwiftUI
    import AppKit
    import ImageIO
    import UniformTypeIdentifiers

Implementation requirements:

1. `struct IconHexagon: Shape` — a regular hexagon with a vertex pointing up,
   matching the in-app `HexagonShape` orientation. Compute vertices as
   `angle = i * .pi / 3 - .pi / 2` for i in 0..<6, radius `min(w,h)/2`.

2. `let gold = Color(red: 0xF5/255, green: 0xB8/255, blue: 0x00/255)` —
   the exact AccentColor value. Do not eyeball a different gold.

3. Two concepts, per 05-UI-SPEC.md:
   - **Concept A ("a") — single hex tile:** one hexagon filling ~70% of the
     1024 canvas (about 720pt across), gold fill, a single bold uppercase "W"
     centred inside at roughly 420pt in `.system(design: .rounded, weight: .bold)`,
     black glyph. Background fills the full canvas.
   - **Concept B ("b") — honeycomb cluster:** seven hexagons in the
     `HexFlowerLayout` arrangement (one centre + six at 60-degree intervals),
     centre tile gold with a black "W", outer tiles a neutral surface tone.
     Scale so the whole cluster occupies ~80% of the canvas.

4. Three appearance variants:
   - `light`: background = white (`Color.white`).
   - `dark`: background = near-black (`Color(white: 0.07)`); keep the gold and
     black glyph; verify contrast still reads (the icon's own background fill
     matters more here than in light mode).
   - `tinted`: render the SAME composition in grayscale — map the gold to a
     light gray (`Color(white: 0.85)`) and the glyph/outer tiles to darker
     grays, over a near-black background. iOS strips colour in tinted mode, so
     the design must carry as a single-tone silhouette without relying on the
     gold/black contrast.

5. Render with `ImageRenderer(content:)`, `renderer.scale = 1`, on a
   `.frame(width: 1024, height: 1024)` root view. Because `cgImage` is
   MainActor-isolated in a top-level script, put the whole render+write in an
   `@MainActor func render(...)` and invoke it with
   `MainActor.assumeIsolated { render(...) }`.

6. Flatten alpha before writing:

        let cs = CGColorSpaceCreateDeviceRGB()
        let ctx = CGContext(data: nil, width: 1024, height: 1024,
                            bitsPerComponent: 8, bytesPerRow: 0, space: cs,
                            bitmapInfo: CGImageAlphaInfo.noneSkipLast.rawValue)!
        ctx.setFillColor(<opaque background CGColor for this appearance>)
        ctx.fill(CGRect(x: 0, y: 0, width: 1024, height: 1024))
        ctx.draw(rendered, in: CGRect(x: 0, y: 0, width: 1024, height: 1024))
        // then CGImageDestinationCreateWithURL(..., UTType.png.identifier as CFString, 1, nil)

7. Exit non-zero with a clear message on any failure (bad args, nil cgImage,
   nil destination) so the verify step fails loudly rather than silently.

Then render the four review images into a scratch directory OUTSIDE the repo
(these drafts are not committed):
`a-light.png`, `a-tinted.png`, `b-light.png`, `b-tinted.png`.
Include the tinted renders in the draft set because tinted-mode legibility is
the highest-risk slot for Concept B (05-UI-SPEC.md flags this explicitly).

Also downscale each draft to 120x120 and 40x40 with
`sips -z 120 120` / `sips -z 40 40` into the same scratch directory, so the
small-size legibility risk 05-UI-SPEC.md calls out for Concept B can actually
be judged rather than assumed.
