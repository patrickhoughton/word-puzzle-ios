<objective>
Wire the spin into the game screen. LetterGridView gains a per-touch mode inside its ONE existing DragGesture (D-01..D-03), draws letter-keyed tiles at rotated offsets (D-07, no commit jump), and an enlarged spin zone. GameView owns the controller and feedback, routes events (ticks, clunk, commit, jackpot sound/haptic), cancels spins before any shuffle (D-15), locks tiles while the ring moves (D-14), gates the spin (D-17, D-20), and resets/cancels on lifecycle changes.

Purpose: This is the user-facing feature.
Output: Modified LetterGridView.swift and GameView.swift.

DECISIONS RECORDED HERE (confirm at the 12-09 on-device checkpoint):
1. Tile touch while the ring is moving (research Open Question 5, orchestrator-adopted): ANY touch except the center tile grabs a moving ring and never types. The center tile does not move, so it falls through to tiles mode, where `isInputDisabled` (true while the ring is active) ignores it. This reconciles D-13 (grab) with D-14 (tiles locked).
2. Double-tap shuffle mid-spin (D-15, planner's call): a tap on a MOVING ring always grabs it and never counts toward the grid's double-tap, so a double-tap on the grid mid-spin grabs and then settles. The background double-tap (outside the grid) and the Shuffle button go through `performShuffle()`, which snaps + commits the ring and then shuffles. A double-tap on the grid shuffles only when the ring was at rest.
3. Side effect to flag (research Pattern 3): tiles are now keyed by LETTER, not slot index, so a regular Shuffle visibly SLIDES tiles between slots (existing spring) instead of cross-fading glyphs in place. This is required so the spin commit is a visual no-op. The user accepts or rejects it at the on-device checkpoint.
4. VoiceOver (D-19): no gameplay spin action is added. The tutorial spin step's VoiceOver escape is the banner action from 12-05.
</objective>
